# Velum

Открытый VPN/прокси-клиент: Flutter + Go + sing-box 1.12.12. Лицензия исходников Velum — GPL-3.0-or-later.

## Что работает

- VLESS, VMess, Trojan, Shadowsocks, Hysteria 2, SOCKS5 и HTTP/HTTPS; поддерживаемые параметры TLS, Reality и транспортов проверяются ядром.
- Импорт одиночных ссылок, списков, Base64 и HTTPS-подписок (до 1 МБ / 500 профилей, без перенаправлений).
- Подписки и отдельные профили: обновление вручную или по расписанию при работающем приложении, поиск, сортировка, избранное, импорт и экспорт резервной копии.
- Правила direct/proxy/block по доменам, CIDR и процессам; применимость зависит от режима маршрутизации и ОС.
- Запуск/остановка sing-box, проверка конфигурации, повторный запуск при аварийном завершении, ручная проверка соединения, TCP-пробы, журнал и статистика трафика.
- Интерфейс по эталону Arena: три вкладки, пять палитр, фоновые узоры, QR профиля и импорт QR из изображения на Linux (требуется `zbarimg`).
- Режим локального HTTP/SOCKS-прокси без повышения прав; TUN с повышенными сетевыми правами.
- Bootstrap имени сервера до установки маршрутов; DNS через DoH внутри прокси после подключения.

Linux GUI собран и протестирован. Go-демон также кросс-компилируется для Windows. Windows получает GUI, службу SCM, токен в ProgramData и TUN через sing-box/Wintun; подробности и ограничения в [docs/windows.md](docs/windows.md). Проверка на реальном Windows-компьютере ещё не выполнялась. Android пока не реализован.

## Быстрый запуск на Linux

Нужны Flutter (проверено на 3.47.9), Go (проверено на 1.27.3), GTK3/CMake/Ninja для Linux UI. Все команды выполняются из корня проекта.

```bash
python3 scripts/init-client.py
make core
make daemon
cd app
flutter pub get
flutter build linux --release
cd ..
```

Первый терминал — служба в режиме локального прокси:

```bash
./bin/velumd --core "$PWD/bin/sing-box" --token-file "$HOME/.config/velum/token"
```

Второй терминал — обычный пользовательский интерфейс:

```bash
./app/build/linux/x64/release/bundle/velum
```

Добавьте свою ссылку/подписку, выберите профиль, нажмите «Подключить». Для proxy-режима настройте приложение на SOCKS5 `127.0.0.1:2080` с DNS через прокси (например, `socks5h`). Системные настройки прокси автоматически не меняются. Секреты не отправляются на сервер Velum: такого сервера нет.

## Проверка рядом с другим VPN

Если уже включён Happ или другой TUN, автоматический выбор интерфейса может выбрать его виртуальный адаптер. На проверенной машине это приводило к таймаутам Reality. Для явного выхода через Wi-Fi используйте:

```bash
./bin/velumd --interface wlan0 --core "$PWD/bin/sing-box" --token-file "$HOME/.config/velum/token"
```

Имя `wlan0` зависит от вашей машины (`ip -brief address`). Флаг не меняет системные маршруты: он привязывает исходящие сокеты ядра к выбранному интерфейсу. При исчезновении этого интерфейса потребуется перезапуск с актуальным именем; автоматическая смена интерфейсов при явной привязке отключена.

## TUN на Linux

Остановите proxy-службу (Ctrl+C). Установите проверенные бинарники в каталог, доступный на запись только администратору:

```bash
sudo install -m 0755 bin/sing-box /usr/local/bin/sing-box
sudo install -m 0755 bin/velumd /usr/local/bin/velumd
sudo /usr/local/bin/velumd --tun --core /usr/local/bin/sing-box --token-file "$HOME/.config/velum/token"
```

GUI продолжает работать от обычного пользователя. Служба не установлена в автозагрузку. Не запускайте от root бинарник из доступной пользователю на запись папки. В TUN весь трафик идёт через выбранный сервер, кроме явно сохранённых исключений. TUN, IPv4/IPv6, DNS через прокси, CIDR-исключение и очистка маршрутов проверены в изолированной Linux-сети с настоящими серверами Hysteria 2 и VLESS Reality/Vision. Это не заменяет проверку в вашей реальной сети с NetworkManager/systemd-resolved.

## Проверки

```bash
make test
cd app
flutter analyze
flutter test
flutter build linux --release
```

Тест жизненного цикла использует отдельный свободный локальный порт.

`make test` требует собранный `bin/sing-box`: проверяет парсинг, ошибки ввода, авторизацию API, конфиги двух протоколов для proxy/TUN и реальный запуск/остановку proxy-процесса. Без бинарника интеграционные тесты Go явно пропускаются.

## Сетевой тест Linux без sudo

```bash
make test-network
```

Нужны собранный `bin/sing-box`, Python 3, OpenSSL, `ip`, `unshare`, `nsenter` и разрешённые ядром user/network namespaces. Скрипт создаёт отдельную сеть, veth-пару, TLS-сертификат, серверы Hysteria 2 и VLESS Reality/Vision, HTTP IPv4/IPv6 и тестовый DoH. Проверяет настоящий TUN, перехват DNS A/AAAA, прямое CIDR-исключение, отключение и SIGTERM. Системный D-Bus отключён только в окружении тестового ядра; настройки DNS основной машины не изменяются. Секреты и сертификат генерируются на время теста. Маршруты основной сети не затрагиваются, Happ отключать не нужно.

## Границы версии 0.1

Статус «Ядро запущено» означает живой процесс, а не подтверждённую доступность VPN-сервера. Без профиля действующего сервера нельзя проверить соединение насквозь. В текущей реализации нет kill switch: при падении службы/ядра обычное соединение может восстановиться. Не считайте эту версию гарантией отсутствия утечек.

Нет MSI-установщика, Polkit, системного трея, фонового обновления подписок при закрытом приложении, AmneziaWG, crypt1 и TV Relay. Windows-служба устанавливается скриптом или из GUI с одним запросом UAC, но не через MSI. Правила процессов не заменяют проверенную реализацию per-app на всех платформах. Перезапуск ядра после аварии не обнаруживает все обрывы сети. Внешние изменения DNS ОС (systemd-resolved/NetworkManager), сторонние VPN, Docker и браузерный DoH требуют сетевых интеграционных тестов. Парольные профили хранятся локально открытым текстом в приватном каталоге, без keyring. Не публикуйте каталог `~/.config/velum`.

HTTPS-подписка загружается GUI по текущему маршруту; до подключения это прямой запрос. Bootstrap имени VPN-сервера использует системный DNS. Отключение IPv6 в настройках само по себе не блокирует IPv6-трафик за пределами туннеля. Неизвестные параметры ссылок отклоняются ядром, а не молча отбрасываются.

В Windows-сборке ACL токена и каталога `%ProgramData%\Velum\bin` настраивается при установке службы, а служба работает от `LocalSystem` из-за прав Wintun и маршрутизации. Каталог профилей пользователя и поведение сторонних VPN-адаптеров отдельно не аудировались; POSIX chmod не является защитой Windows ACL. Wintun, восстановление маршрутов/DNS и установка через UAC ещё не проверены на реальном Windows-компьютере. Не распространяйте Windows-сборку как готовый безопасный VPN-клиент до этой проверки.
