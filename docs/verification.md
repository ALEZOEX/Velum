## Дополнительная проверка Linux

Повторно пройдены Flutter analyze, 4 Flutter-теста и Go test -race / vet. Найдена и исправлена ошибка сборки: go install без ldflags создавал ядро с версией unknown, которое служба отклоняла при старте. Makefile теперь устанавливает constant.Version=1.12.12, добавлен TestBuiltCoreVersion. Запуск настоящей службы проверен.

Воспроизводимый тест `make test-network` запускает настоящую службу и ядра в отдельных user/network namespaces, без sudo и без замены маршрутов основной системы:

- Hysteria 2: HTTP IPv4 и IPv6 через TUN, адрес исходящего соединения подтверждён на сервере.
- DNS A/AAAA: UDP запрос к тестовому внешнему DNS перехвачен TUN, обработан DoH внутри прокси; получены ожидаемые IPv4/IPv6 адреса.
- Отключение: удалён velum0, восстановлены исходные policy rules обеих версий IP.
- CIDR-исключение: origin видит прямой адрес клиента вместо адреса сервера туннеля.
- VLESS Reality + XTLS Vision: HTTP через настоящий TUN и сервер Reality, с локальным TLS handshake-сервером и временной парой ключей.
- SIGTERM службы: дочерний процесс завершён, TUN и policy rules удалены.

Системный D-Bus намеренно недоступен тестовому ядру: интеграция с host systemd-resolved не входит в эту изолированную проверку. Физическая сеть продолжает использовать Happ; Tailscale и Docker не отключались. Проверка не доказывает отсутствие всех утечек на физическом интерфейсе и не проверяет DPI, мобильную сеть, сон или kill switch.

### Проверка с пользовательским сервером

После импорта профилей в GUI проверен выбранный VLESS Reality-профиль. Первоначально два HTTPS-запроса через SOCKS5 завершились таймаутом. Диагностический запуск показал, что автоматический исходящий интерфейс — happ-xray. Изменение только исходящего интерфейса на wlan0 дало HTTP 200. Добавлен CLI-флаг службы --interface, проверка существования интерфейса и TestExplicitInterfaceConfig с проверкой реальным ядром.

После пересборки штатная служба запущена с --interface wlan0. Запросы через socks5h://127.0.0.1:2080 к https://example.com и https://www.cloudflare.com/cdn-cgi/trace вернули HTTP 200, curl ssl_verify_result=0, примерно 0.37–0.39 с. Содержимое trace и адрес пользователя не сохранялись. Служба оставлена работающей в proxy-режиме для ручной проверки GUI. Ссылки, UUID и ключи профилей в отчёт не включены.

Повторно пройдены 7 Go-тестов с race detector / vet и весь изолированный сетевой тест после добавления --interface. Маршруты и policy rules основной Linux-сети совпадают с исходными, Happ продолжает работать. Это подтверждает работу выбранного сервера через физический Wi-Fi, но не является проверкой системного TUN на основной машине.

## Расширение клиента

После переработки интерфейса пройдены `flutter analyze`, 15 тестов Flutter, Go test с race detector и vet, а также восемь проверок `make test-network` в изолированной сети. Проверки включают импорт и обновление подписок, сохранение данных и интерфейс в широком и узком окнах. Они не подтверждают полную совместимость с Happ или INCY и не проверяют новую версию на реальном пользовательском VPN-соединении. Действовавшие служба и соединения не перезапускались.
