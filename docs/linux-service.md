# Системный TUN на Linux

Локальный SOCKS/HTTP-прокси сам по себе не перенаправляет трафик приложений. Для системной маршрутизации Velum использует TUN и отдельную привилегированную службу; Flutter-интерфейс запускается обычным пользователем.

## Установка

Из корня проверенной копии репозитория сначала соберите бинарники и подготовьте токен **от обычного пользователя**:

```bash
python3 scripts/init-client.py
make core daemon
```

Если для XHTTP используется Xray companion, сначала соберите или загрузите проверенный `bin/xray`. Установщик включит его только при наличии этого файла. Версии и способы проверки ядра определены сборкой проекта; установщик сам не скачивает исполняемые файлы.

Прочитайте `scripts/install-linux-service.sh`, затем выполните:

```bash
sudo ./scripts/install-linux-service.sh
```

Установка запросит системный пароль. При прямом запуске от root или из другого контекста явно укажите владельца GUI:

```bash
sudo ./scripts/install-linux-service.sh --user alezoex
```

Пользователь определяется из `SUDO_USER` либо `PKEXEC_UID`; домашний каталог — из базы пользователей ОС. Установщик не использует `$HOME` процесса root для поиска токена. Для нестандартного каталога конфигурации доступен `--config-dir /полный/путь`; GUI должен использовать тот же каталог через `VELUM_CONFIG_DIR`.

После установки откройте сетевые настройки Velum, выберите **TUN** и подключите профиль. Установка и запуск службы разрешают создание TUN, но сами не подключают VPN и не изменяют выбранный профиль. Служба автоматически запускается при загрузке ОС, а пользовательское подключение по-прежнему управляется GUI.

Если одновременно используется Happ или другой VPN, сначала отключите его туннель перед проверкой системной маршрутизации Velum. Установщик не отключает сторонние VPN. При необходимости можно явно выбрать физический исходящий интерфейс:

```bash
sudo ./scripts/install-linux-service.sh --interface wlan0
```

Имя интерфейса зависит от машины. При явной привязке переход Wi-Fi/Ethernet не происходит автоматически; без параметра используется автоматическое определение интерфейса ядром.

## Конфликт с ранее запущенной proxy-службой

Интерфейс API занимает `127.0.0.1:27841`. Если этот порт занят вручную запущенным `velumd`, установщик откажется запускать новую службу. Остановите старый процесс в том терминале, где он запущен, и повторите команду. Установщик не завершает процессы по имени или номеру порта.

Для установки файлов без запуска:

```bash
sudo ./scripts/install-linux-service.sh --no-start
sudo systemctl enable --now velum.service
```

## Что устанавливается

- `/usr/local/lib/velum/velumd`, `sing-box` и при наличии `xray`: владелец root, режим 0755; каталог недоступен на запись обычному пользователю.
- `/etc/velum/token`: приватная root-копия существующего GUI-токена, режим 0600; значение не выводится. Каталог имеет режим 0700.
- `/etc/systemd/system/velum.service`: системная служба с `--tun`, политикой `KillMode=control-group`, ограниченными сетевыми capabilities и отдельным каталогом `/run/velum`.

Профили и настройки пользователя не копируются в системные каталоги и не меняются. Привилегированный процесс получает выбранный профиль через авторизованный локальный API. Один экземпляр службы рассчитан на одного владельца GUI-токена. При смене токена или владельца повторите установку.

Обновление устанавливает подготовленные бинарники и сохраняет резервную копию предыдущих файлов до успешного старта. Если запуск или авторизованная проверка API не проходят, установщик восстанавливает предыдущие файлы и состояние systemd. Проверка API подтверждает готовность службы и разрешение TUN; она не доказывает доступность конкретного VPN-сервера или отсутствие утечек в вашей сети.

## Диагностика и удаление

```bash
systemctl status velum.service
sudo journalctl -u velum.service -n 80 --no-pager
sudo systemctl stop velum.service
sudo ./scripts/uninstall-linux-service.sh
```

Удаление останавливает службу и дочерние ядра, убирает unit, системные бинарники и системную копию токена. Пользовательские профили, настройки и исходный токен сохраняются. Остановка systemd дожидается штатной очистки TUN ядром; аварийные случаи SIGKILL или отключения питания требуют отдельных проверок восстановления сети. Kill switch этим установщиком не добавляется.

Настройки жизненного цикла и ограничений сверены с официальной документацией [systemd.exec](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html) и [systemd.service](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html). Реальная установка требует системной авторизации и должна проверяться отдельно от проверки синтаксиса скриптов.
